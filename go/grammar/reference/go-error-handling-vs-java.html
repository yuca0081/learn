错误处理对照 Java

第 3 课配套速查表 · 建议打印贴墙 · 返回第 3 课

七条铁律

  1. error 永远是最后一个返回值；nil = 成功。
  2. 失败时其他返回值给零值：return 0, err。
  3. err 要么处理要么上抛，不能静默丢弃（丢弃也须显式 _ =）。
  4. 包装错误用 %w（保留链），别用 %v（链断）。
  5. 判断错误：值 → errors.Is，类型 → errors.As。
  6. 资源关闭用 defer，紧跟获取成功的判断之后。
  7. 业务失败一律 error 不 panic；recover 基本只活在框架里。

基础 idiom

result, err := doSomething()
if err != nil {
	return 0, fmt.Errorf("doSomething 失败: %w", err)  // 加上下文并上抛
}
// 走到这里 err == nil，安心用 result

哨兵错误 / 自定义错误类型

var ErrNotFound = errors.New("记录不存在")            // 哨兵：只需判断"是不是"
return fmt.Errorf("查用户: %w", ErrNotFound)
errors.Is(err, ErrNotFound)                           // true

type ValidationError struct {                         // 自定义类型：要携带数据
	Field string
	Msg   string
}
func (e *ValidationError) Error() string {            // 实现 error 接口（隐式）
	return fmt.Sprintf("%s: %s", e.Field, e.Msg)
}
return &ValidationError{Field: "port", Msg: "超范围"}
var ve *ValidationError
errors.As(err, &ve)                                   // ≈ catch (ValidationError e)

defer

f, err := os.Open(path)
if err != nil {
	return err
}
defer f.Close()          // 函数任何出口（含 panic）前执行
// 多个 defer：LIFO（后注册先执行）
// 参数在 defer 语句处求值（之后改变量不影响）
// recover() 只在 defer 的函数里有效
