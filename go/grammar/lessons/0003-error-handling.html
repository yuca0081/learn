Go for Java Engineers · Lesson 03

错误处理：error、defer 与 panic

预计 30 分钟 · 前置：第 2 课 复合类型 · 学完你能：读懂并写出惯用的 if err != nil、错误链包装、defer 资源清理，知道什么时候才轮到 panic

本课目标：这是你从 Java 搬家时惯性最重的一站——你会本能地想找 try-catch。Go 没有（业务代码里没有），它的答案是：错误就是一个普通的返回值。本课学完，你写 Go 的手感就基本齐了。卡住随时回对话里问我。

1 · error 是值：第一次见面

Java
int port = parsePort("8080");
// 失败 = 抛异常，控制流
// 隐形跳走（隐形 goto）
// 签名里看不见（throws 可省）
// 不 catch 也可能编译通过
Go
port, err := parsePort("8080")
if err != nil {
	return 0, err     // 失败 = 一个
}                     // 普通的返回值
fmt.Println(port)

三条惯例，全社区的 Go 代码都长这样：

  1. 可能失败的函数，最后一个返回值是 error；err == nil 表示成功。
  2. 失败时其他返回值返回零值（return 0, err），调用方拿到 err 就不会用前面的值。
  3. 拿到 err 要么处理、要么往上传，不能假装没看见（写成 _ 丢弃也得是显式的）。

为什么这么设计？Go 官方的立场写在 Rob Pike 的文章 Errors are values 里：错误就是值，可以像普通值一样传递、检查、包装、组合。代价是 if err != nil 满天飞（Java 里那些隐形的异常跳转，在 Go 里全部平铺在你眼前）；收益是看函数签名就知道它会怎么失败，看代码就知道错误去哪了——没有暗处的控制流。这其实是 Java 受检异常（checked exception）的初衷，Go 只是用"值 + 惯例"来实现，不靠编译器强制。

官方教程：A Tour of Go · 错误（basics 尾部）；《Go 语言圣经》§5.4 错误。

2 · 造错误与错误链：%w、errors.Is / errors.As

import "errors"
import "fmt"

// 造一个新错误（哨兵错误：定义成包级 var，调用方好判断）
var ErrNotFound = errors.New("记录不存在")

// 包装底层错误并加上下文：%w 是关键字占位符，会把底层错误"串"进链里
_, err := os.ReadFile("config.yaml")
if err != nil {
	return fmt.Errorf("读配置失败: %w", err)
}

错误一路往上 return 的过程中，每层用 %w 加一点上下文，最后在顶层得到一条链——Java 里对应异常的 caused by。检查链上的错误用两个函数，直接对应你的直觉：

GoJava 对照用途
errors.Is(err, ErrNotFound)e == MyCodes.NOT_FOUND / 哨兵比较链上是不是这个错误（值）
errors.As(err, &myErr)catch (MyException e) / instanceof链上有没有这种类型的错误，有则取出来
if errors.Is(err, ErrNotFound) {
	http.NotFound(w, r)      // 链上某处是"记录不存在"
	return
}
记住用 %w 而不是 %v：%v 只是把错误信息拼进字符串，链断了，上层 errors.Is 就认不出来了。想保留"是什么错误"的判断能力，一律 %w。

示例查询：Go by Example · Errors（中文）；官方博客 Working with Errors in Go 1.13。

3 · 自定义错误类型

想给错误携带结构化信息（错误码、字段名），定义一个 struct 并实现 Error() string 方法即可——不需要 implements 关键字，Go 的接口是隐式满足的（第 4 课细讲，这里照抄格式就行）：

type ValidationError struct {
	Field string
	Msg   string
}

func (e *ValidationError) Error() string {   // 有这个方法，它就是 error
	return fmt.Sprintf("%s 校验失败: %s", e.Field, e.Msg)
}

// 造：return &ValidationError{Field: "port", Msg: "超出 1-65535"}
// 查：
var ve *ValidationError
if errors.As(err, &ve) {                     // ≈ catch (ValidationError e)
	fmt.Println("坏字段:", ve.Field)           // 结构化信息都在
}

选型口诀：只需要"是不是这个错" → 哨兵变量 var ErrXxx = errors.New(...) + errors.Is；需要携带数据 → 自定义类型 + errors.As。Java 的"异常层级体系"在 Go 里就这么朴素。

4 · defer：finally 的替身，但更顺手

资源关闭是错误处理的另一半。Go 用 defer 把"清理动作"挂在函数出口上：

Java
try (var f = new FileReader(p)) {
    // 使用 f
}   // 自动 close()
// 或 finally { f.close(); }
Go
f, err := os.Open(p)
if err != nil {
	return err
}
defer f.Close()   // 函数任何出口
                  // 都会执行
// 使用 f ...

defer f.Close() 的意思是"无论这个函数从哪个 return 离开（哪怕 panic），返回前都执行 f.Close()"。功能上就是 try-with-resources / finally，但获取资源和登记释放写在一起，不会漏。三个特性：

defer fmt.Println("first")
defer fmt.Println("second")
// 输出顺序：second、first —— 多个 defer 栈式执行（LIFO）

x := 1
defer fmt.Println("x =", x)   // 参数在这里就求值了
x = 2
// 退出时打印 x = 1，不是 2 ！想打印最终值就传指针或不带参
社区惯例：defer 紧跟在资源获取成功判断的后面，一行关一件事。数据库连接、锁、HTTP 响应体，全都是这个节奏。

示例查询：Go by Example · Defer（中文）；官方教程：A Tour of Go · Defer。

5 · panic / recover：留给真正的异常

panic ≈ Java 里抛出去没人接的 RuntimeException：栈一路展开、程序崩溃退出。数组越界、nil 指针解引用、nil map 写入——这些你前两课见过的崩溃，全是运行时自动 panic。

errorpanic
语义预期内的失败（文件不存在、参数非法、网络超时）不该发生的程序 bug（越界、nil 解引用、init 失败）
处理方式if err != nil 正常处理崩溃；或顶层 recover 兜底
Java 心智受检异常 / Optional.empty未捕获 RuntimeException / Error

业务代码几乎永远该用 error，不要用 panic 做控制流——这条直觉你可以直接从 Java 搬过来（"别用异常做流程控制"）。recover 只在 defer 的函数里有效，用来把 panic 捞回来：

func safeDiv(a, b int) (result int) {
	defer func() {                      // 匿名函数 + defer = 出口钩子
		if r := recover(); r != nil {   // r 就是 panic 的值
			result = 0                  // 兜底，程序不崩
		}
	}()
	return a / b                        // b == 0 时 panic: integer divide by zero
}

日常业务代码里你几乎不写 recover——它主要活在框架里（比如 Web 框架给每个请求包一层 recover，单个请求崩了不影响进程）。见到时认识即可。

官方教程：A Tour of Go · Panic、Recover；示例查询：Go by Example · Panic（中文）。

6 · 动手练习：把"抛异常"翻译成"返回错误"

任务：下面是典型的 Java 校验方法（解析 + 抛异常 + 多 catch）。翻译成 Go：错误一路包装（%w），范围错误用哨兵变量，main 里用 errors.Is 区分处理。写完贴进 Go Playground 验证。

待翻译的 Java
public class PortUtil {

    public static int parsePort(String input) {
        int port = Integer.parseInt(input);          // 可能抛 NumberFormatException
        if (port < 1 || port > 65535) {
            throw new IllegalArgumentException(
                "端口必须在 1-65535: " + port);       // 抛自定义信息
        }
        return port;
    }

    public static void main(String[] args) {
        for (String s : new String[]{"8080", "abc", "99999"}) {
            try {
                System.out.println("OK: " + parsePort(s));
            } catch (NumberFormatException e) {
                System.out.println("不是数字: " + s);
            } catch (IllegalArgumentException e) {
                System.out.println(e.getMessage());
            }
        }
    }
}
// 期望输出: OK: 8080 / 不是数字: abc / 端口必须在 1-65535: 99999
查看参考答案（先自己写！） 
package main

import (
	"errors"
	"fmt"
	"strconv"
)

var ErrPortRange = errors.New("端口必须在 1-65535")   // 哨兵错误

func parsePort(input string) (int, error) {
	port, err := strconv.Atoi(input)
	if err != nil {
		return 0, fmt.Errorf("不是数字 %q: %w", input, err)  // %w 保留底层错误
	}
	if port < 1 || port > 65535 {
		return 0, fmt.Errorf("%w: 得到 %d", ErrPortRange, port)
	}
	return port, nil
}

func main() {
	for _, s := range []string{"8080", "abc", "99999"} {
		port, err := parsePort(s)
		if err != nil {
			if errors.Is(err, ErrPortRange) {          // ≈ catch (IllegalArgument)
				fmt.Println(err)
			} else {                                    // 其他解析错误
				fmt.Println("不是数字:", s)
			}
			continue
		}
		fmt.Println("OK:", port)
	}
}
// 输出: OK: 8080 / 不是数字: abc / 端口必须在 1-65535: 得到 99999

自评清单：① 函数签名是 (int, error)，失败时返回 0, err？② Atoi 的 err 用了 %w 包装而不是丢弃？③ 范围错误是包级哨兵 var ErrPortRange？④ main 里用 errors.Is 区分了两种失败？⑤ 没有任何 panic / try-catch 式的东西？

8 · 闭卷回忆

  1. error 在返回值列表的什么位置？err == nil 代表什么？
  2. %w 和 %v 包装错误的区别是什么？errors.Is 和 errors.As 各对应 Java 的什么？

核对答案
  1. 最后一个；成功。
  2. %w 保留错误链（Is/As 还能识别），%v 只是拼字符串；Is ≈ 哨兵值比较，As ≈ catch (Xxx e) / instanceof。
  3. LIFO 栈式执行、参数在 defer 语句处求值；panic 留给程序 bug 和不可恢复状态，业务失败一律 error。
