Go for Java Engineers · Lesson 02

切片、map、struct 与方法

预计 30 分钟 · 前置：第 1 课 基础语法 · 学完你能：用 slice / map / struct 组织数据、给 struct 写方法，并把一个 Java 类翻译成 Go

本课目标：这一课学完，你就具备了写"真正的程序"的数据组织能力。好消息是：slice ≈ ArrayList、map ≈ HashMap、struct ≈ 类的字段部分，直觉大多可以搬过来。真正的新东西只有一个：struct 是值，赋值即复制。遇到问题随时回对话里问我。

1 · 切片 slice ≈ ArrayList

Go 有定长数组 [3]int，但日常几乎不用——主角是切片（动态数组）。把 ArrayList 的直觉带过来就行：

scores := []int{90, 85, 77}   // 字面量创建，≈ new ArrayList<>(List.of(90,85,77))
scores = append(scores, 60)   // 追加元素
fmt.Println(len(scores))      // 4

var s2 []int                  // 零值是 nil 切片——可以直接 append，不用先初始化
s2 = append(s2, 1)

nums := make([]int, 0, 100)   // 预留 100 容量，≈ new ArrayList<>(100)，纯优化
本课第一条铁律：append 可能扩容并返回新的切片头，所以必须接住返回值：s = append(s, x)。写成单独一行 append(s, x) 是编译错误（evaluated but not used）。这种"函数返回新值"的风格和 Java 的 list.add()（原地修改）相反。

切片支持左闭右开的子切片，子切片和原切片共享底层数组：

sub := scores[1:3]   // 下标 1、2，不含 3 —— 和 Java substring 的区间约定一样
sub[0] = 999         // 注意：scores[1] 也变成 999 了！

日常编码记住两层即可：用 append 增、用 s[i] 改、用 len(s) 量；"共享底层"这个坑先有个印象，读到别人代码里出现 s[a:b] 时能想起这回事。

示例查询：Go by Example · Slices（中文）；深入原理：《Go 语言圣经》§4.2 切片。

2 · map ≈ HashMap

ages := map[string]int{
	"张三": 28,                // 字面量创建
}
ages["李四"] = 35               // 写入 / 更新

n := ages["王五"]               // 读：键不存在 → 返回 int 零值 0，不报错
v, ok := ages["张三"]           // comma-ok 惯用法：ok 表示键是否存在
delete(ages, "李四")            // 删除

stock := make(map[string]int)  // make 创建空 map，≈ new HashMap<>()

v, ok := m[key] 是你会天天写的惯用法，对应 Java 里 containsKey + get 两步合一步。而 Java 的 getOrDefault(k, 0) 在 Go 里就是直接下标读——缺失键返回零值。

本课第二条铁律（最容易 panic 的地方）：var m map[string]int 的零值是 nil，读 nil map 安全（返回零值），写 nil map 直接 panic：assignment to entry in nil map。所以作为 struct 字段或函数局部变量时，先 make 再写。对比记忆：nil 切片能 append，nil map 不能写。
map 遍历顺序是随机的（官方故意加了随机化，逼你不要依赖顺序）。Java 的 LinkedHashMap 那种"记住插入顺序"的 map，Go 标准库没有——需要顺序时惯用做法是维护一个平行的 key 切片。

示例查询：Go by Example · Maps（中文）；《Go 语言圣经》§4.3 map。

3 · range：统一的遍历写法

for i, v := range scores {     // 切片：下标 + 值，≈ Java 的 for (int i = 0; ...)
	fmt.Println(i, v)
}
for _, v := range scores {     // 不要下标，用 _ 丢弃
	fmt.Println(v)
}
for i := range scores {        // 只要下标

}

for name, age := range ages {  // map：键 + 值，≈ entrySet()
	fmt.Println(name, age)
}

位置固定：第一个是下标/键，第二个是值；不用的那个用 _ 丢掉。第 1 课学的 for 三形态加 range，就是 Go 遍历的全部。

示例查询：Go by Example · Range（中文）。

4 · struct 与值语义

Go 没有 class，数据结构用 struct 定义——就是把 Java 类里"字段"那一半搬出来：

type Player struct {
	name string     // 小写：仅包内可见（第 1 课的规则对字段同样适用）
	hp   int
}

p1 := Player{name: "勇者", hp: 100}   // 字面量，字段名必须写全
fmt.Println(p1.name, p1.hp)           // 点号访问，和 Java 一样

不初始化也行——struct 的零值是"所有字段取各自零值"。现在，本课真正的新知识来了：

Java
Player p1 = new Player();
p1.hp = 100;
Player p2 = p1;   // p2 和 p1
                  // 是同一个对象！
p2.hp = 50;
// p1.hp == 50
Go
p1 := Player{name: "勇者", hp: 100}
p2 := p1        // 复制整个 struct
                // 是两个独立的值！
p2.hp = 50
fmt.Println(p1.hp)  // 100，p1 没变

Java 的对象变量天生是引用；Go 的 struct 变量就是值本身，赋值和传参都会整体复制。这是两种语言最深的一道分水岭，比任何语法差异都重要。好处是你不用想"这个对象会不会被别人改"——默认不会被改；想要共享，下一节的指针就是干这个的。

赋值时JavaGo
ArrayList / HashMap共享引用slice 共享底层数组；map 整个共享（和 Java 一样）
对象 / struct共享引用复制整个值（要共享得显式用指针 &）

《Go 语言圣经》§4.4 结构体；示例查询：Go by Example · Structs（中文）。

5 · 指针速成：两分钟版

Go 的指针就是"显式化的 Java 引用"，只是没有运算：

p3 := &p1        // 取地址，p3 的类型是 *Player（读作"Player 指针"）
p3.hp = 80       // 通过指针改字段：自动解引用，等价 (*p3).hp = 80
fmt.Println(p1.hp)   // 80 —— 这次 p1 变了

&p1        // & 取地址（≈ 拿到 Java 里那个"对象本身"）
*p3        // * 解引用（顺着地址找到值）—— 日常代码里很少要你手写
// 没有指针算术：p3+1 这种 C 操作不存在，比 C 安全得多

心智模型一句话：Java 把"引用"做成了默认且唯一；Go 让你选——不写 & 就是复制，写 & 就是共享。零值 nil 指针 ≈ Java 的 null（解引用 nil 会 panic ≈ NPE，体感完全一样）。

6 · 方法：接收者就是显式的 this

方法就是"带接收者参数的函数"，接收者写在 func 和方法名之间，相当于 Java 的 this，但由你自己命名：

func (p Player) Name() string {    // 值接收者：拿到的是副本（只读场景）
	return p.name
}

func (p *Player) Heal(n int) {     // 指针接收者：通过指针改到原值
	p.hp += n
}

func main() {
	p := Player{name: "勇者", hp: 100}
	p.Heal(20)                     // 调用方式完全一样，Go 自动取地址
	fmt.Println(p.Name(), p.hp)    // 勇者 120
}

什么时候用哪种？规则就一条：方法要修改接收者 → 必须指针接收者（值接收者拿到的是副本，改了也白改）。社区惯例是：同一个 struct 的方法接收者类型保持一致，而实际项目里绝大多数 struct 都统一用指针接收者。

没有构造函数：Go 没有 Java 的 new Player() 构造器语法，惯用写法是提供一个 NewXxx() 函数返回 *Xxx。练习里会用到。

官方教程：A Tour of Go · 方法；示例查询：Go by Example · Methods（中文）。

7 · 动手练习：把 Java 类翻译成 Go

任务：下面是一个典型的 Java 类（字段 + 三个方法）。把它翻译成 Go：struct + map 字段 + 三个方法 + 一个 main 验证。要求用指针接收者，并想一想为什么。写完贴进 Go Playground 运行验证。

待翻译的 Java
import java.util.HashMap;
import java.util.Map;

public class Inventory {
    private Map<String, Integer> stock = new HashMap<>();

    public void add(String item, int n) {
        Integer cur = stock.get(item);
        if (cur == null) {
            stock.put(item, n);
        } else {
            stock.put(item, cur + n);
        }
    }

    public int count(String item) {
        Integer cur = stock.get(item);
        return cur == null ? 0 : cur;
    }

    public int total() {
        int sum = 0;
        for (int n : stock.values()) {
            sum += n;
        }
        return sum;
    }
}

// 验证：add("苹果",3); add("苹果",2); add("香蕉",5);
//      期望 count("苹果")==5, total()==10

提示：Go 的 Add 会比 Java 版短得多——想想 nil map 铁律的另一面：缺失键读出来是什么？

查看参考答案（先自己写！） 
package main

import "fmt"

type Inventory struct {
	stock map[string]int
}

func NewInventory() *Inventory {          // 构造器惯例
	return &Inventory{stock: make(map[string]int)}  // 字段必须 make，否则写 nil map panic
}

func (inv *Inventory) Add(item string, n int) {
	inv.stock[item] += n                  // 缺失键读到 0，+= 直接成立，不用判 null
}

func (inv *Inventory) Count(item string) int {
	return inv.stock[item]                // 缺失返回 0，天生就是 getOrDefault
}

func (inv *Inventory) Total() int {
	sum := 0
	for _, n := range inv.stock {         // 只用值，键用 _ 丢弃
		sum += n
	}
	return sum
}

func main() {
	inv := NewInventory()
	inv.Add("苹果", 3)
	inv.Add("苹果", 2)
	inv.Add("香蕉", 5)
	fmt.Println(inv.Count("苹果"), inv.Total())  // 5 10
}

自评清单：① NewInventory 里对字段做了 make？② 三个方法都用指针接收者（Total 只读，值接收者也行——但惯例是保持统一）？③ Add 和 Count 里没有任何 == null 判断？④ range 时用 _ 丢弃了键？⑤ 方法名大写（Add 而不是 add），保持导出惯例？

9 · 闭卷回忆

60 秒，不看上文回答三个问题，再翻到下面核对：

  1. append 为什么必须重新赋值给切片变量？
  2. 读 nil map 里缺失的键会发生什么？往 nil map 写呢？nil 切片能 append 吗？
  3. p2 := p1（两个都是 struct 变量）之后改 p2 的字段，p1 变吗？想共享怎么做？
核对答案
  1. 扩容时底层会换新数组，append 返回新切片头；不接住就可能丢数据，且单独调用是编译错误。
  2. 读：安全，返回值类型零值；写：panic；nil 切片可以直接 append（三者对比着记）。
  3. 不变——struct 赋值是整体复制；想要共享用 & 取指针（或方法用指针接收者）。
