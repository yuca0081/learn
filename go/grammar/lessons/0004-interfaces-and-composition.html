Go for Java Engineers · Lesson 04

接口与组合：没有继承的面向对象

预计 30 分钟 · 前置：第 3 课 错误处理 · 学完你能：读懂标准库的接口设计，用隐式实现、小接口和嵌入写出 Go 风格的抽象，并把一个 Java 接口 + 多实现翻译成 Go

本课目标：Java 的"面向对象"三大件是类、继承、接口；Go 砍掉了继承，把接口做成隐式实现。这不是功能缺失，而是 Go 设计哲学的核心——行为看方法集，抽象看小接口，复用靠组合。这也是读懂标准库的钥匙：读完请完成 翻译练习 和 检索测验。

1 · 隐式实现：没有 implements 关键字

Java 里类型和接口是声明时绑定的——类必须写 implements Notifier。Go 里类型和接口是编译器按方法集匹配的：只要类型拥有接口要求的全部方法，它就自动满足该接口，类型本身根本不需要知道接口的存在：

Java
interface Notifier {
    void send(String msg);
}

// 必须显式声明 implements，
// 还必须 import 这个接口
class EmailNotifier
        implements Notifier {
    @Override
    public void send(String msg) {
        System.out.println("邮件: " + msg);
    }
}
Go
type Notifier interface {
	Send(msg string)
}

type EmailNotifier struct{}

// 没写 implements——方法齐了就满足
func (EmailNotifier) Send(msg string) {
	fmt.Println("邮件:", msg)
}

// 想编译期确认？一行断言：
var _ Notifier = EmailNotifier{}

这叫隐式实现，相当于"静态版鸭子类型"：编译器不看血统声明，只看方法集。威力在于——你可以给别人包里的类型"补"一个接口视角，一行代码都不用改人家。比如标准库的 http.ResponseWriter 没实现任何叫 Stringer 的东西，但你可以随时定义一个只含 Write(p []byte) (int, error) 的小接口，它就自动满足。

var _ Notifier = EmailNotifier{} 这个写法值得记住：_ 丢弃赋值，只留下编译检查——类型不满足接口时这里直接编译报错，是最便宜的单测。

官方教程：A Tour of Go · 接口。

2 · Go 的接口哲学：小接口 + 消费者定义

Java 社区的接口常常 3–5 个方法起步，接口跟着实现者走（UserServiceImpl 旁边放个 UserService）。Go 反过来：

  • 接口越小越好。标准库的招牌接口几乎都只有 1 个方法：error（Error() string）、fmt.Stringer（String() string）、io.Reader、io.Writer。Rob Pike 的谚语："The bigger the interface, the weaker the abstraction."（接口越大，抽象越弱。）
  • 接口定义在消费者包里，不是实现者包里。谁用这个抽象，谁定义它长什么样——这样接口只包含消费者真正需要的方法，实现者也不用 import 消费者。
  • 惯用法：accept interfaces, return structs。函数参数收接口（灵活），返回值给具体类型（信息全）。和 Java 里"返回值也声明成接口"的习惯相反。

你在第 3 课已经用过这套哲学了——error 就是个只有 Error() string 一个方法的接口，你写的 *ValidationError 没声明任何东西，就自动成了 error。

3 · 接口值的真面目：一对（类型，值）

Java 的接口引用底下就是一个普通对象引用；Go 的接口值内部是两个词：动态类型 + 动态值。这个模型解释了一个著名的坑：

type MyErr struct{}
func (e *MyErr) Error() string { return "boom" }

func main() {
	var p *MyErr = nil
	var err error = p      // 装进接口：类型是 *MyErr，值是 nil
	fmt.Println(err == nil) // false！接口有类型就不等于 nil
}
nil 陷阱：接口值 == nil 当且仅当类型和值都是 nil。把一个具体类型的 nil 指针装进接口，接口就不是 nil 了——Java 里 (Exception) null == null 是 true，Go 里对应场景是 false。铁律：返回 error 时要么返回真 nil，要么返回有效错误，别返回具体类型的 nil 指针。

4 · 方法集规则：*T 的方法不借给 T

第 2 课讲过值接收者和指针接收者，它们和接口相遇时有一条硬规则：

  • 方法用值接收者 (t T) → T 和 *T 的方法集都有它 → 两者都能满足接口。
  • 方法用指针接收者 (t *T) → 只有 *T 的方法集有它 → 只有 *T 能满足接口。
type Counter interface{ Next() int }

type counter struct{ n int }
func (c *counter) Next() int { c.n++; return c.n }

var _ Counter = &counter{}  // ✅ 指针满足
var _ Counter = counter{}   // ❌ 编译错误：Next 是 *counter 的方法

原因很朴素：接口值装箱后拿不到可寻址的副本，编译器没法替你 (&x).Next()。实战推论：方法集里有任何一个指针接收者方法，就统一全用指针接收者，然后把 &T{} 装进接口。这是你在 Go 里最常见的报错之一。

5 · 组合而不是继承

接口嵌入：小接口拼成大接口

Java 用 extends 扩展接口；Go 直接把接口嵌入接口：

type Reader interface{ Read(p []byte) (int, error) }
type Writer interface{ Write(p []byte) (int, error) }

type ReadWriter interface {   // ≈ extends Reader, Writer
	Reader
	Writer
}

标准库的 io.ReadWriter、io.ReadWriteCloser 全是这么拼出来的。接口方法少到 1 个，再用嵌入自由组合——这就是 Go 标准库抽象的积木逻辑。

struct 嵌入 ≠ 继承

Java · extends
class Animal {
    String name;
    String describe() {
        return "我是 " + name;
    }
}

class Dog extends Animal {
    @Override
    String describe() {       // 多态覆盖
        return "汪！我叫 " + name;
    }
}

Animal a = new Dog();  // is-a，向上转型
a.describe();          // 动态绑定 → "汪！"
Go · 嵌入
type Animal struct{ Name string }
func (a Animal) Describe() string {
	return "我是 " + a.Name
}

type Dog struct {
	Animal        // 嵌入：字段/方法提升
	Loud bool
}

d := Dog{Animal: Animal{Name: "旺财"}}
d.Name        // 提升字段，直接访问
d.Describe()  // 提升方法，语法上像自己的

// 没有 override，没有多态：
// Dog 不是 Animal 的子类型
能力Java extendsGo 嵌入
复用字段与方法（少写代码）✅✅ 提升到外层，直接 d.Name / d.Describe()
is-a 关系 / 向上转型✅ Animal a = new Dog()❌ var a Animal = d 编译错误（d.Animal 才是）
覆盖 + 动态多态✅ 调谁由运行时类型决定❌ 内层方法不知道自己被嵌入，永远不会回调外层
访问"父类"super.xxx()没有 super，显式写 d.Animal.Describe()

所以 Java 里你想用继承的地方，Go 的答案是两件套：要多态 → 定义小接口 + 各类型各自实现；要复用 → struct 嵌入。继承能干的两件事，Go 拆开各给了一个更简单的机制。

6 · 类型断言、type switch 与 Stringer

类型断言 ≈ instanceof

var v any = "hello"        // any = interface{}，Go 的 Object

s := v.(string)            // 断言：不是 string 直接 panic（≈ 强转）
s, ok := v.(string)        // 安全版：不符时 ok=false，不 panic

switch x := v.(type) {     // type switch ≈ instanceof 链 / 模式匹配
case string:
	fmt.Println("字符串, 长度", len(x))
case int:
	fmt.Println("整数:", x)
default:
	fmt.Println("其他")
}

Java 16+ 的 if (v instanceof String s) 模式匹配和 type switch 神似。处理 any（空接口）时，type switch 是标准姿势；对自己定义的接口，尽量别下断言——那是没设计好接口的信号。

String() 方法 ≈ toString()

type Player struct{ Name string; Lv int }

func (p Player) String() string {           // 实现 fmt.Stringer
	return fmt.Sprintf("%s(Lv.%d)", p.Name, p.Lv)
}

fmt.Println(Player{"Gopher", 3})  // Gopher(Lv.3)——fmt 自动调 String()

和 Java 的 toString() 完全同构：fmt 家族打印时发现值实现了 Stringer 就自动调用。你的 %v 输出难看？给类型加个 String() 就好。

官方教程：类型断言、Stringer；Go by Example：Type Switches。

7 · 动手练习：把 Java 翻译成 Go

任务：把下面的 Java 翻译成 Go。覆盖本课要点：接口、两个隐式实现、接口切片（多态容器）、range 遍历——顺带复习第 2 课的 struct 和方法：

待翻译的 Java
import java.util.List;

interface Shape {
    double area();
}

class Circle implements Shape {
    double r;
    Circle(double r) { this.r = r; }
    public double area() { return 3.14159 * r * r; }
}

class Rect implements Shape {
    double w, h;
    Rect(double w, double h) { this.w = w; this.h = h; }
    public double area() { return w * h; }
}

public class Main {
    // 计算任意一组图形的面积总和
    public static double totalArea(List<Shape> shapes) {
        double sum = 0;
        for (Shape s : shapes) sum += s.area();
        return sum;
    }

    public static void main(String[] args) {
        System.out.println(totalArea(List.of(new Circle(2), new Rect(3, 4))));
        // 期望输出: 24.56636
    }
}

先自己写，贴进 Go Playground 验证输出是 24.56636，再对照答案：

查看参考答案（先自己写！） 
package main

import "fmt"

type Shape interface {
	Area() float64
}

type Circle struct{ R float64 }

func (c Circle) Area() float64 { return 3.14159 * c.R * c.R }

type Rect struct{ W, H float64 }

func (r Rect) Area() float64 { return r.W * r.H }

func totalArea(shapes []Shape) float64 {   // 参数收接口
	sum := 0.0
	for _, s := range shapes {
		sum += s.Area()
	}
	return sum
}

func main() {
	shapes := []Shape{Circle{R: 2}, Rect{W: 3, H: 4}}
	fmt.Println(totalArea(shapes))  // 24.56636
}

自评清单：① 接口只有一个方法 Area() float64？② Circle / Rect 都没写任何 implements，靠方法集自动满足？③ 接收者用的值接收者（只读不改，不需要指针）？④ 切片的元素类型是接口 Shape，两种 struct 混着装？⑤ 遍历用 for _, s := range？——五条全中，你就把"没有继承的多态"跑通了。

9 · 闭卷回忆

最后 60 秒，不看上文回答三个问题，再滚动到底部核对：

  1. Go 类型怎样才算实现了某个接口？想编译期确认怎么写？
  2. 指针接收者方法对"谁能满足接口"有什么影响？
  3. struct 嵌入和 Java 继承的两条关键区别是什么？
核对答案
  1. 把接口要求的方法全部定义出来（隐式实现）；var _ 接口 = 类型值{} 编译期断言。
  2. 指针接收者的方法只在 *T 的方法集里，所以只有 *T 能满足接口；值类型装进接口直接编译错误。
  3. 没有 is-a / 向上转型（Dog 不是 Animal）；没有覆盖和动态多态（内层方法不会回调外层）。提升来的只是"语法糖"。
